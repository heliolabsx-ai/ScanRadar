## What it is

Two scanners sharing one data pipeline, with alerts and a web dashboard at **https://scanradar.tech**:

1. **Ranking scanner** — every minute, scores all ~200 NSE F&O stocks and ranks them bull/bear. Modelled on a commercial scanner Saurabh showed (card per stock: % change, OI build-up label, VWAP side, volume delta, order block, S1/S2/R1/R2, R:R, conviction score, rank/percentile, "top 3 picked" rule).
2. **Rule scanner** — Chartink-style conditions on 5-min candles (e.g. `[=3] High <= [=2] Close`), defined as JSON in `scans/`, fire Telegram alerts with cooldown.

Goals beyond the reference products: rank by **relative strength vs sector** rather than raw % change; log every signal and its outcome so the scanner grades itself (hit rate per setup); replay/backtest scans over stored candles. None of the "better than" features are built yet — see To-do.

## Architecture

```
Kite WebSocket ──► ingest ──► Postgres/TimescaleDB (candles_1m, daily_ref, instruments, alerts, scan_snapshots)
                      │
                      └──► Redis (live:{sym} forming candle, ref:{sym}, scan:latest, pub/sub)
                                  │
                   engine ◄───────┘  (subscribes candles:closed; runs analytics + rule scans; Telegram)
                      │
                   api (FastAPI) ──► web/index.html (static dashboard)  ◄── Caddy (HTTPS, basic auth)
```

Compose services: `postgres`, `redis`, `ingest`, `engine`, `api`, `caddy` (host network). All config via `.env` (see `.env.example`; never commit `.env`).

### ingest/ (Python 3.12, kiteconnect 5.x)
- `main.py` — scheduler: 08:55 login + universe + daily refs; 09:14 open WS; every minute flush closed candles to Postgres and forming candle to Redis; 15:31 finalize last candle, close WS and **exit the process** (Docker restarts it; KiteTicker's twisted reactor cannot be restarted in-process). If started mid-session on a weekday it runs setup immediately. Ticks outside 09:15–15:30 update OI only, no candles. Historical calls go through `_hist()` (0.4 s pacing, retry on 429). `ingest:status` in Redis shows setup progress or `error: ...`.
- `kite_auth.py` — `session(R)` reuses the Redis-cached token if Kite still accepts it (a fresh login invalidates the previous token for the api_key), else TOTP auto-login → request_token → access_token (cached in `kite:access_token`, 20 h TTL). The Connect redirect chain is walked hop-by-hop so an unreachable/401 callback URL doesn't lose the token; TOTP codes are never resubmitted within one 30 s window. `KITE_PASSWORD` empty = manual-token mode.
- `preflight.py` — first-day check: `docker compose run --rm ingest python preflight.py` (session, universe, historical with OI, 20 s WS sample in market hours).
- `universe.py` — NFO FUT nearest expiry ⋈ NSE EQ → `(symbol, eq_token, fut_token)`; static `SECTOR` map (extend as needed; unmapped → OTHERS).
- `candles.py` — tick → 1-min OHLCV; volume delta by tick rule (uptick = buy); futures FULL-mode ticks supply OI.
- Equity subscribed in QUOTE mode, futures in FULL mode (OI only comes in FULL).
- **NIFTY 50 index (3 Nov 2026, for the Alarms board).** Token 256265 (`candles.INDEX_TOKEN`), subscribed in QUOTE mode with the equities. `candles.split_ticks()` pulls its ticks out before the stock code, so the index never enters `symbols`/`state`, the ranking, the candles or the tick watchdog (a dead stock feed still reads as silent). `candles.IndexState` builds 1-minute OHLC from `last_price` (no volume/OI/delta; outside 09:15–15:30 a tick only updates the price; a tick without `last_price` is skipped without dropping the batch's stock ticks). Persisted to its **own table `index_1m(ts, symbol 'NIFTY50', open, high, low, close)`**, never `candles_1m`, in `flush()` **after** the stock candles and inside its own try/except (never fatal; a failure logs `index flush failed`). Redis: `index:NIFTY50` = JSON `{ltp, prev_close, pct, ts}` with **ts = the last index tick** (not the flush) and a 30-minute TTL; `flush()` rewrites the key only when the last index tick advanced (module-level `index_written_ts`), so a stalled feed's key stops refreshing and expires, and `api/alarms.index_fresh` (max age 180 s against the board's `at`) shows no NIFTY chip once the last tick is older than 3 minutes; `index:NIFTY50:prev_close` (24 h) is set by `load_index_ref()` right after `load_daily_refs` in the morning setup (daily history call, never fatal). History: `docker compose run --rm ingest python backfill.py --index [--days 60]` also fills `index_1m` (gap-fill, `ON CONFLICT DO NOTHING`); `--index-only` skips the stock loop and implies `--index`.

### engine/
- `analytics.py` — per symbol: % change, VWAP, OI % vs prev-day OI, OI label via price×OI matrix on a **30-min intraday trend** (long/short build-up, unwinding, covering), classic pivots from prev H/L/C, opening range (first 15 min), RVOL vs 20-day avg 1-min volume, order block = origin candle of largest 5-bar impulse, stop/target/R:R. `score()` = relative move×18 + OI confirmation + VWAP side + RVOL + R:R.
- `rules.py` — JSON rule DSL. Sides: `{"number":x}`, `{"series":"prev_day_close|prev_day_high|prev_day_low|day_low|day_high"}` (`day_*` = today's extreme over the bars seen so far, forming bar included; added 27 Oct 2026), `{"off":N,"field":"open|high|low|close|volume|vwap|oi"}` (`off` 0 = forming bar; add `"sma":n` / `"ema":n` for a moving average ending at that bar, added 19 Oct 2026; **derived candle fields `range` (high − low), `body` (|close − open|), `upper_wick`, `lower_wick`, added 4 Nov 2026** via `rules.DERIVED`/`_field`, usable with `off` and `sma`/`ema`; an unknown field name fails closed like a missing column); any side takes `"mul":x` (Chartink's `* 3`). `core.backtest.max_offset` asks for the whole day when a rule uses an EMA or a day series. **`"continuous": true` (27 Oct 2026)** = Chartink's cross-session series: the previous stored session's bars sit in front of today's (`rules.join_sessions`, `attrs["session_start"]` keeps `day_*` today-only), so `off` 1 at 09:15 is yesterday's last bar; engine `prev_session_bars(tf)` loads them once per day, replay `alerts.prev_session_frames`, `backtest.fires(..., prev1m=)`. Timeframes 1m/3m/5m/15m/30m/60m resampled from 1-min with 09:15 anchor. `match` all|any. **Scan-owned levels (19 Oct 2026):** optional `"trade": {"stop": SIDE|{"pct"}, "target": SIDE|{"pct"}|{"rr"}}` resolved at the fire minute by `rules.trade_levels()`; engine stores `stop/target/levels` in the alert payload, replay (`api/alerts._trade_payload`) and the desk use the same; fallback to pivot levels when absent or on the wrong side.
- **PD fade additions to the DSL (2 Nov 2026, `feat/pd-fade`).** `engine/rules.py` stays a byte copy of `core/rules.py` (the engine image copies `engine/` only): mirror every change and check with `cmp core/rules.py engine/rules.py`. `"hours": {"from": "HH:MM", "to": "HH:MM"}` = the scan fires only when the fire minute (bar close, IST) is `from <= t < to` (from inclusive, to exclusive; strict zero-padded `HH:MM`, `to` after `from`); `hours_window(scan)` parses it once, `in_hours(scan, ts, window)` tests a minute; honoured by the engine, `core.backtest.fires`/`fires_naive` and the alert replay; no block = always. `"min_rr": x` = the scan's own R:R floor (0 = none) in place of `DESK_ALERT_MIN_RR` (1.5), read through `rules.min_rr(scan, default)` by `trades.candidates` and `live_desk.process_minute`; caveat: a `DESK_MIN_RR` above 0 still gates the desk's verdict on such a scan through `live_desk.gate()` (the Trades queue reads `min_rr` alone), and the skip text then names the scan's floor, not `DESK_MIN_RR`. `validate_scan(scan)` raises on a malformed `hours` block or a `min_rr` that is not a non-negative number; `engine.load_scans` and `api/alerts.scan_files()` both log and drop that one file, so a bad scan never silences the others or aborts `_prepare_day`. `"alert": {"telegram": "silent"}` = sent with `disable_notification` (the message arrives, the phone does not buzz; `telegram(text, silent=False)` in `core/notify.py` and `engine/notify.py`, `ingest/notify.py` stays loud-only); the engine puts `silent` in its `tg:defer:{day}` items, `live_trades.flush_deferred` honours it, and so do the engine's direct sends (failed push, `TRADES_LIVE=0`). `"story": {"line": "prev_day_high"|"prev_day_low", "template": "..."}` → `rules.story(scan, bars, ctx)` = `{line, break_at, run_px, run_pct}` from the bars the scan saw at the fire minute: `break_at` = close minute (bar start + timeframe) of the **first** bar today closing through the line in the scan's direction (short: above, long: below), so a day with two breaks reports the first; `run_px` = the extreme (max high short, min low long) from that bar to the last closed bar (the forming bar is left out); `run_pct` its signed % from the line, 1 dp; None without a break. Stored as `payload.story` live (engine) and on replay (`ensure_replay_alerts`). Templates format with `{symbol}`, `{at}` (fire minute), `{line}`, `{break_at}`, `{run_px}`, `{run_pct}`; a template that does not format is logged and the plain text goes out. `rules.alert_text(scan, symbol, price, lv, st, now)` is the engine's Telegram text as a pure function (tests `tests/test_engine_alert_text.py`): scan name and symbol HTML-escaped (Telegram rejects a bare `&`: M&M, GVT&D); with a story, the header's SELL/BUY and the `entry ₹… · stop ₹… (day high) · target ₹… (prev close) · R:R 1:x` line only for a scan with a `trade` block (a break note carries `side` for the chip colour only). The stop label says "(day high)"/"(day low)" because the stop is the whole day's extreme, not the run since the break (ruled over the spec's "(run high)").
- `main.py` — on each `candles:closed` message (debounced 20 s): load today's candles + forming bar, analyse, rank (TOP_N=3 per side, R:R ≥ 1.5 to be "picked"), write `scan:latest` to Redis + `scan_snapshots` to Postgres, evaluate every `scans/*.json`, insert `alerts`, send Telegram (cooldown key `cooldown:{scan}:{symbol}` in Redis; since 31 Oct 2026 the message is queued on `tg:defer:{day}` for the API's trades loop, `TRADES_LIVE=0` sends directly)). Since 2 Nov 2026 it skips a scan outside its `hours`, resamples each symbol once per timeframe per run (`rules.resampler(frames)`, a per-(symbol, tf) cache shared by every scan; callers must not mutate the frames), stores `payload.story`, builds the text with `rules.alert_text` and queues `silent` with it.
- `notify.py` — Telegram sendMessage.

### core/ (shared analytics, added 17 Oct 2026)
`analytics.py` and `rules.py` are byte-identical copies of the engine's (the engine switches to importing them in Phase 2, see the design doc). `asof.py` defines the one as-of semantic (`view_at`: complete bars `ts < at` + a flat stub of the `at` bar). `ranking.py` `rank()` is the engine's score/rank/picked logic as a function. `backtest.py` `fires()` replays a scan over a day with the live view at every minute (proven equal to the naive definition by tests) and `outcome()` grades a trade. Since 2 Nov 2026 `fires()`/`fires_naive()` honour a scan's `hours`: a minute outside the window never fires and never starts a cooldown. Tests in `tests/` run with `.venv/bin/python -m pytest tests -q` (`requirements-dev.txt`).

### core/patterns.py (added 18 Oct 2026)
Double/triple bottom/top detector on 5m bars: `detect_day(df1m, prev_close, params)` emits each pattern's lifecycle tagged with the minute it became knowable (bar close), `as_of(patterns, at, ctx)` filters to a minute and scores (extended ≥1 %, OI lower at the second point, volume ≥1.5× avg, sector agrees, VWAP side; sixth check = confirming close). Pairing: a new swing pairs with the most recent earlier qualifying swing; a later second point supersedes the earlier double (or extends it to a triple). `DEFAULTS` tuned 18 Oct (see `docs/superpowers/notes/patterns-backtest-2026-10-18.md`); `detector_hash()` keys stored rows. **v4 (19 Oct 2026, Saurabh's spec):** nine checks (`CHECKS`), score of 8: + exhaustion (second point's swing bars traded less than the first's), breakout volume (confirming close ≥ 1.5× the median of the pattern's bars; also a **gate** via `breakout_vol`, a quiet close stays forming and a target reached without a confirming bar abandons), breakout delta (tick-rule delta with the direction). Target = nearest prev-day pivot beyond the neckline at least one height away, else `target_mult`×height (`facts.target_basis`). A shape re-forming on a failed pattern's stop+neckline within `retest_bars` is state **retest** (`facts.retest_of/retest_until`, clock-based). `summarise()` splits by score ≥5 and by the breakout-volume tick. **v5 (19 Oct 2026):** new finders on the same lifecycle — `_head_shoulders` (shoulders within `shoulder_tol`, head beyond by `hs_head`, neckline = second trough), `_flag` (pole ≥ `pole_min` in `pole_bars`, then `flag_min..flag_max` bars of drift within half the pole; expires), `_ranges` (last three swings of each kind: flat/flat = rectangle emitting both sides, flat top + rising lows = ascending triangle, mirror = descending; `abandon_level` = far side of the box), opening-range break (first `orb_bars` bars, break by `orb_until`, created already triggered). `LABELS`, `CONTINUATION` (extension and OI checks flip), `confidence(stats, kind, score, state)` = recorded hit rate in the score bucket, served on every row as `confidence` and shown in the Conf column. **v6 (26 Oct 2026, after "many triggers, few targets"):** `last_trigger` 14:00 (forming shapes abandoned after it), `facts.target1` = measured move (T1, graded as `outcome.hit_t1`/`tt1_min`; T2 stays the pivot target), tenth check *with the tape* from breadth (`breadth_at` in `detect_frames`, `tape_long`/`tape_short`), `CHECKS`=10 / score of 9, Trade-grade default pill (conf ≥45, score ≥5), `PATTERN_MIN_CONF` default 45. 42-day T1 hit: H&S 88 %, triple top 78 %, inverse H&S 69 %, triple bottom 67 %, double bottom 66 %, range breakdown 66 %, double top 64 %, ORB 57/60 %; flags and triangles still 25–45 % (`docs/superpowers/notes/patterns-backtest-v6-2026-10-26.md`). `summarise(rows)` gives per-kind stats. `core/calendar.py` = copy of `ingest/tradingday.py`; `core/notify.py` = copy of `engine/notify.py` (engine keeps its own until Phase 2).

### core/timemachine.py, core/sizing.py, core/gate.py, api/trades.py, api/live_trades.py (trade loop, added 31 Oct 2026)
Every trigger the desk would judge gets one `trade_rows` row: replay odds, size in cash shares, the day gate and, later, the outcome. **Replay** (`core/timemachine.py`, pure): from the trigger's 5-minute bar (`trigger_bar`: the bar whose close is the trigger minute) to `flat_by`, `monte_carlo` rebuilds the rest of the day `N_PATHS` = 4,000 times (`SEED` 19) by drawing each future bar's h/o, l/o, c/o ratios from a random past session that has a bar at that time, and `past_sessions` runs the same plan at the same % distances on each past session; one first-touch rule (a bar touching both levels counts as the stop). `replay(plan, hist)` uses the last `SESSIONS` = 60 stored sessions strictly before the plan's day, `None` without any. Verdict word, checked in order: `flat` (none ≥ 75 %), `coin` (T1 and stop within 8 points), `edge` (T1 ahead), `bad`; shown as "cannot resolve by close / coin flip / odds favour T1 / odds favour stop" (`live_trades.WORDS`, `ScanTrades`). The odds are replays of past sessions: every word of copy says so, never a forecast, never "will". **Sizing** (`core/sizing.py`): `shares(entry, stop, settings, side)` = min(⌊max_loss / distance⌋, ⌊capital × position_cap / entry⌋) whole cash shares, 0 with `limited_by` `zero_distance` or `delivery_no_short`; `DEFAULTS` capital ₹5,00,000, max_loss 2,000, day_loss 6,000, max_trades 5, position_cap 0.6, product intraday, flat_by 15:20; `validate()` raises naming the field. **Gate and ledger** (`core/gate.py`, pure): `ledger(rows, settings)` counts **only rows logged as paper trades** (`paper` set; Saurabh's option B): committed = risk of logged open rows, realised and realised_losses from settled ones, taken, the open symbols, `gate_state` CLOSED when taken ≥ max_trades or committed + losses + max_loss > day_loss. `blocked_total`/`blocked_won` **exclude BLOCK rows he logged anyway** (an override cost him nothing). `gate()` BLOCKs on, in order: max trades, day risk, zero shares, already open in the symbol; advisory, nothing is placed. `settle()` grades every row, logged or not, on 1-minute bars cut at `flat_by` through `core.backtest.outcome`: a touch exits at the level with `settled_at` = **the touching bar's close** (start + 1 min); an untouched row settles **at `flat_by`** at the last close before it (backfilled days' equity bars end 15:14). **Storage** (migration `005_trades.sql`, mirrored in `db/init.sql`): `trade_rows` UNIQUE (day, ref), refs as in `desk_calls` (`pattern:SYM|kind|formed_at`, `alert:ID`); `target` = T1 (`facts.target1`) for patterns and the scan's target for alerts, **`target2`** = the pattern's pivot target (runner, not graded); JSONB `odds`, `size` (with a settings snapshot), `outcome`, `paper` `{logged_at, note}`; `rows_for_day` adds a computed **`label`** (pattern display name or scan name), not a stored column. `trade_settings('current')` holds the settings (Postgres, because the loop needs them). **Queue** (`trades.candidates`): exactly the desk's filters (pattern score/R:R gate, `PATTERN_MIN_CONF`, `DESK_ALERT_MIN_RR`, scans with `"desk": false` left out, live staleness `DESK_MAX_AGE_MIN`); each pattern trigger is **judged as of its own trigger minute**, so a trigger that failed later keeps its row; a rule alert within **60 min of the (scan, symbol) pair's last alert that got a row** gets none (the repeat rule anchors on rows, not on any earlier alert). Rows before `TRADES_RULES_FROM` (default 2026-11-03) have **`gate` NULL** and the tab says "rules not applied". Settled days are backfilled by `backfill_day` inside every `_prepare_day` (idempotent; afterwards Redis `tradesdone:{day}`, 30-day TTL), the ledger cut at each candidate's minute; **backfilled rows use today's confidence window** (`setup_stats(now)`), not the stats as of that day. `_HIST` caches `(symbol, day)` → history (≤ 60 entries per process, other days dropped each minute; reads 120 calendar days of candles). **One minute loop** (`live_trades.run`, started with the API, ~:20 s past each minute in a worker thread): trades tick (09:20–15:30 on trading days, gated on the minute so 15:30 runs: new rows, Redis keys backfilled, tombstones, open rows settled, final at `flat_by`) → `flush_deferred` (always) → desk tick (when the desk is on); the pattern tick still runs in its own process pool at ~:05 s. Redis: `trades:{day}:{ref}` = JSON `{odds, size, gate, gate_reason}` or **an empty-string tombstone** for a live alert that gets no row (its message then goes out at once, plain), 1-day TTL; `tg:defer:{day}` = list of `{ref, text, ts}` pushed by the engine (rule alerts, unless `TRADES_LIVE=0`) and the pattern loop, sent with the odds line once the key exists, plain after 90 s without one, dropped after 30 min; channel `trades:updated` → WS `{"type":"trades"}`. Telegram line: `T1 39 % · stop 42 % · coin flip · 229 sh · PASS` (or `BLOCK: <reason>`, `no history`). **Routes:** `GET /api/trades?day&at` → `{day, at, applied, rules_from, settings, ledger, rows, pending}` (rows cut at `at`; pending = settled day with no rows and no `tradesdone` marker, which kicks `_prepare_day`), `GET`/`PUT /api/trades/settings` (400 names the field), `POST /api/trades/{id}/paper` `{note}` (logs once; a repeat returns the logged row). `/api/patterns` (cut at `at`) and `/api/alerts` (per day, and today's for the live list) rows gain `odds` and `trade` `{id, shares, risk_inr, gate, gate_reason}` joined by ref. Desk: `verdict_context` gains `odds` and `gate {state, reason}`, the ticket's `size` is the shares dict (from the row, else from the settings); the verdict prompt gained two sentences: the odds block is a replay of the stock's own past sessions, to argue with and cite, never obey; a BLOCK means the day's rules are spent, so the call cannot be take. **Redeploying during market hours:** `docker compose up -d --build engine api` also recreates `ingest` (engine depends on it) — on 27 Oct 2026 that cost ~4 minutes of candles at 14:15. Use `docker compose up -d --build --no-deps engine api` in session, or deploy after 15:30.

**Engine and API deploy together (since 31 Oct 2026):** a new engine with an old API queues rule-alert Telegrams in `tg:defer:{day}` that nothing sends, and they are dropped after 30 minutes. Apply a pending migration first (`005_trades.sql` for the trade loop), then `docker compose up -d --build --no-deps api engine`. `TRADES_LIVE=0` in `.env` (engine recreated) is the rollback switch: rule alerts go straight to Telegram as before.

**Pull and rebuild in one command (since 2 Nov 2026):** outside market hours, with no dashboard page open on a settled day in between, and any `backtest_scan.py` run only after it:
```bash
cd /opt/scanradar && git pull && docker compose up -d --build --no-deps api engine && docker compose logs --tail 30 engine
```
Scans ship with `git pull` and both containers read the mounted `scans/` at once, so between the pull and the rebuild the old API would replay new scans with old code (pivot-grading the PD break notes) and the old engine would ignore `hours` and `silent`. `ALERT_SCHEMA` in `api/alerts.py` salts the scan hash, so replay rows the old API built are recomputed after the rebuild: a slip costs a replay recompute, not wrong rows. Then the logs of both show no traceback and no `bad scan` line; the engine logs no scan count and reads `scans/` only when candles arrive, so a bad file surfaces in its log from 09:15 (the API logs it whenever it lists the scans: replay preparation, the trades minute).

**Alarms board deploy (3 Nov 2026):** apply `006_alarms.sql` first, piped via stdin (`docker compose exec -T postgres psql -U scanner -d scanner < db/migrations/006_alarms.sql`: the container's `/migrations` mount is stale), then rebuild **api, engine and ingest** (`docker compose up -d --build api engine ingest`; this one included ingest for the index subscription, done at night, when ingest is idle), then `docker compose run --rm --no-deps ingest python backfill.py --index --index-only --days 60`. API and engine ship together again (the engine records its direct sends in `deliveries`, the API the queued ones). **The web is a read-only Caddy mount (`./web:/srv/web:ro`), so a web-only change ships with `git pull` alone**, no rebuild; bump the `?v=` token of a changed helper so browsers refetch it.
